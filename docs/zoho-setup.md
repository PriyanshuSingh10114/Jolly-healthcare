## Configure Creator

1. Create the app from scratch and implement the [forms and permission sets](../creator/schema/model.md). Verify link names in Creator.
2. Set form workflows for validation on create/edit using `creator/deluge/validate-*.deluge`. In the Formulations On Validate workflow, append the timestamp snippet from `creator/deluge/stamp-sync.deluge` after substituting the sync identity's email address. Verify that API edits trigger this workflow. Use Added Time as the sync log timestamp.
3. Create the admin-only Deluge function `seed_demo`, paste its body from `creator/deluge/seed.deluge`, and execute it in Creator. Alternatively enter the three rows from the private CSV into the two related forms and assign each Plant_Reference in the UI.
4. Confirm the three formulation lookups. Verify the RFQ identity can see previous submissions in RFQ_Receipts and cannot read the full RFQ report or plant reports. Test validation using the Creator API identity as well as the UI.
5. Configure two regional OAuth clients or grants. The RFQ grant needs Creator report READ and form CREATE. The sync grant needs both Creator scopes plus report UPDATE and Commerce items CREATE and UPDATE. Consent in the regional Zoho API Console using the intended identities. Provision refresh tokens directly in the shell or host secret manager.

## Obtain the OAuth grants

Sign in to the regional Zoho API Console as the intended integration user. Create a Self Client, open Generate Code, enter the relevant comma-separated scopes from the API guide, and generate a short-lived grant code. Exchange it with an HTTPS POST to the regional Accounts host at /oauth/v2/token. Send form fields grant_type=authorization_code, client_id, client_secret and code. Keep only the returned refresh token and client credentials in the integration environment or secret manager. Repeat for the second grant and confirm that its user has the required roles in both apps. Avoid echoing values to the terminal or committing any token output. [Zoho Self Client authorization code flow](https://www.zoho.com/developer/oauth/self-client/authorization-code-flow.html)

## Configure Commerce

1. Create a dedicated store. Configure Restrict out of stock purchases, enable tracked inventory for these demo items, leave inventory at zero and suppress cart, price and Buy Now blocks in the available templates. Avoid enabling payment methods and retail channels for this demo.
2. Run sync and confirm the three product records exist in Commerce admin. Install the catalog section following deployment instructions.
3. Keep sample/demo retail items off the dedicated storefront. Inspect the home, mobile menu, product, search and collection templates, and direct cart/checkout entry paths as a signed-out buyer. Keep the native records hidden if any retail surface leaks the nominal price or permits purchase. The Zoho-hosted custom catalog still displays the synchronized public fields in that configuration.

Zoho documents native Quote Requests as a Premium feature. Its preferences include Hide Price and Hide Add to Cart, and the native form writes to Commerce Pending Quote Requests. Keep every buyer-facing RFQ action bound to the Creator-backed modal. If native quote buttons cannot be removed independently, retain the custom catalog with hidden native items.
